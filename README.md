# AI Code Review Dashboard 设计方案

本文档提供一套**“产品级 + 管理级”**的 AI Code Review Dashboard 设计方案。
**核心目标**：
1. **工程师视角**：看得懂、愿意用，能切实提升开发效率。
2. **管理层视角**：一眼看懂 ROI（投入产出比），量化团队效能提升。

---

## 一、设计原则 (Design Principles)

一个好的 AI Code Review Dashboard 不在于堆砌数据，而是要**证明三件事**：
1. **Usage（用得多）**：产品真正融入了开发流程。
2. **Quality（有价值）**：发现了人工难以发现的真问题。
3. **ROI（省成本）**：切实节省了时间和人力成本。

**指标设计标准**：
* **可量化** (Quantifiable)
* **可对比** (Comparable/Trendable)
* **通俗化** (Readable)

---

## 二、四大核心指标维度 (Core Metrics)

### 1. 使用情况（Usage）
**价值主张**：“AI Review 已融入日常开发流程，而非试用工具。”

| 核心指标 | 说明 |
| :--- | :--- |
| **Review 次数** | 每日/周产生的 Review 总量 |
| **活跃用户数** | 真正使用工具的开发者数量 |
| **覆盖项目数** | 接入 AI Review 的项目范围 |
| **人天节省（总）** | 基于规则换算的总体人天节省 |


### 2. 审查质量（Quality）
**价值主张**：“AI 提出的建议中，**XX%** 被开发者采纳，有效提升了代码质量。”

| 核心指标 | 说明 |
| :--- | :--- |
| **发现问题总数** | AI 提出的 Issue 总量 |
| **严重问题数** | Error / High Risk 级别的问题数 |
| **采纳率** | 开发者点赞、复制或修改的比例（核心信任指标） |
| **误报率** | 开发者忽略或点踩的比例 |

---

## 三、可视化试图详解 (Visualization Strategy)

本方案构建了代码质量监控的**“战术试图”**（单次提交分析）和**“战略视图”**（长期趋势分析）。

### 1. 战术视图：风险四象限散点图 (Risk Quadrant)
**核心逻辑**：每一个点代表一个提交的文件。通过**“变更行数”**与**“问题数量”**的二维分析，快速定位风险。

```text
(Y轴：AI 发现的问题数 / Issue Count)
      ▲
      │
  💣  │  🚨
左上角 │ 右上角
(精密) │ (灾难)
      │
──────┼──────▶ (X轴：变更行数)
      │
  💤  │  ✅
左下角 │ 右下角
(琐碎) │ (健康)
      │
```

* **🚨 右上角 (灾难区)**：改动巨大且报错满屏。**动作**：Team Lead 立即暂停合并，严查代码。
* **💣 左上角 (精密陷阱)**：改动极少但报错多（如正则错误、逻辑漏洞）。**动作**：重点 Review，防微杜渐。
* **✅ 右下角 (健康开发)**：新功能开发，代码量大但质量高。
* **💤 左下角 (琐碎修补)**：改注释、修格式。**动作**：快速通过。

### 2. 战术视图：变更风险矩形树图 (Change Risk Treemap)
**解决方案**：基于**“增量风险”**，展示本次变更的危险程度。

* **矩形面积 (Size)** = `Lines Changed` (改动幅度)
* **矩形颜色 (Color)** = `Risk Score` (AI 发现的问题密度/严重度)

**视觉解读**：
* 🟥 **大红块**：核心模块大改且问题多 -> **通过阻断，人工介入**。
* 🟩 **大绿块**：大规模重构但逻辑安全 -> **快速扫视**。
* 🟥 **小红块**：小改动大风险（逻辑炸弹） -> **仔细排查**。

### 3. 战略视图：多项目分组堆叠柱状图 (Quality Histogram)
**核心逻辑**：诚实地展示工作量与风险的比例，不通过平均化掩盖问题。

* **X轴**：时间周期（天/周）
* **分组**：不同项目并排展示
* **堆叠**：
    * **上层（红色）**：风险代码当量（含毒量）
    * **下层（蓝色）**：净产出代码量（高质量代码）

**视觉解读**：
* **高大蓝柱**：团队高效产出，质量稳健。
* **戴红帽子的柱子**：负债累积，红色越厚，Code Review 压力越大。
* **全红矮柱**：逻辑炸弹，代码量虽少但全是问题。

## 四、进阶价值指标 (Advanced Insights)

### 1. 共性问题洞察
**价值**：AI Review 不只发现问题，还在持续提升团队编码规范。

* **常见问题排行榜**：Top N 团队常犯错误。
* **问题趋势变化**：随着时间推移，某类低级错误是否逐渐减少。
* **开发者痛点榜**：团队最容易出错的编码点。

### 2. Bug 热点分析
**价值**：精准治理问题高发模块，拒绝经验主义。

* **高风险模块 Top List**：建议重构或加强测试的区域。
* **问题严重度分布**：清晰展示错误与警告的比例。

### 3. 可视化图表实现参考
以下是进阶图表的具体实现建议与数据绑定方式：

| 图表名称 | 展示方式 | 说明 | 示例数据字段绑定 |
| :--- | :--- | :--- | :--- |
| **常见问题排行榜** | Top N 排行柱状图 / 条形图 | 按出现次数排序，快速定位团队普遍问题 | `issue_type`, `issue_count` |
| **问题趋势变化** | 折线图 | 每周/每 Sprint 各类问题数量变化趋势 | `issue_type`, `week`, `issue_count` |
| **问题严重度分布** | 饼图 / 环形图 | 错误 vs 警告比例，风险等级分布 | `severity`, `count` |
| **开发者痛点榜** | 词云 / 舆情雷达图 | 团队最容易出错的编码点（从建议内容提取关键词） | `violations.category`, NLP 关键词抽取 |

## 五、价值话术模板 (Value Proposition)

用于向不同角色汇报时的“一句话价值”：

* **To 工程师**：
> “它能帮你提前发现低级错误，减少 Code Review 时的无效扯皮，让你专注于核心逻辑。”

* **To Team Lead**：
> “它能让你一眼看到本次提交的风险点在哪里，告别靠感觉盲猜，精准分配 Review 精力。”

* **To 老板 / 管理层**：
> “AI Code Review 本季度已覆盖 **90%** 核心项目，节省了 **XX** 人天审查成本，并成功拦截了 **XX** 个潜在严重 Bug，同时推动了团队编码规范的自动化落地。”

### 布局设计原则

| 层级 | 区域名称 | 核心目的 | 目标受众 |
| :---: | :--- | :--- | :--- |
| **L1** | 核心指标卡片 | 3 秒内传达关键 KPI | 所有角色 |
| **L2** | 使用趋势图 | 判断团队进步/退步趋势 | TL / 管理层 |
| **L3** | 质量分析双栏 | 问题类型分布，定位短板 | TL / 工程师 |
| **L4** | 反馈详情列表 | 具体问题追踪，下钻到代码行 | 工程师 |

---

### 响应式建议

| 端 | 布局策略 |
| :--- | :--- |
| **桌面端 (≥1200px)** | 双栏布局，L3 区域左右并排，充分利用横向空间 |
| **平板端 (768px - 1199px)** | L3 区域改为上下堆叠，其余保持不变 |
| **移动端 (<768px)** | 单栏堆叠，优先展示 L1 指标卡片和 L2 趋势图 |
